# Direct personal shelf

AppShelf is this Mac's default for new personal apps. A signed AppShelf bootstrap was installed on Coppertino, and Lucas confirmed that CLIDeliveryCheck build 5 installed and opened through the shelf after a push-triggered delivery. TestFlight remains an explicit alternative.

The implementation uses private `lucaswkuipers/AppShelf-builds` release assets and a separate private UIKit client, `lucaswkuipers/AppShelf`. The phone gets only a fine-grained Contents read-only artifact token, like Hop. Source and signing credentials remain on the Mac. The publisher uses Lucas's personal GitHub CLI login on the Mac and verifies repository ownership and privacy before writes.

Commands:

```sh
uikit-app setup-direct --device <personal-iPhone-UDID> --name <device-name>
uikit-app package <project-directory> --build <number>
uikit-app direct <committed-project-directory>
uikit-app setup-shelf-refresh
uikit-app setup-shelf-installs
uikit-app refresh-shelf
```

The machine-wide `delivery: shelf` setting makes `create` install the shelf push workflow and save that choice in `.uikit-app.json`; the same `publish` command waits for its `available-in-shelf` result. `--delivery testflight` overrides the route for a new app. Existing projects without a delivery field keep TestFlight. Do not leave two push-triggered delivery workflows in one app.

An explicit `publish` starts the workflow if the commit skipped CI or no push run appeared within 90 seconds. It checks the remote commit before dispatching and prevents concurrent publish waiters. If GitHub has accepted a dispatch but has not listed it after another 90 seconds, it reports pending; resume with `publish`, without manually dispatching another workflow. A completed publish reuses its existing run. Failed runs still require fixing the reported failure or rerunning that workflow.

Accepted dispatches are recorded per app and commit in `~/.config/uikit-app/workflow-dispatches`, so restarting the CLI does not dispatch again merely because GitHub has delayed listing the run. If a run was intentionally deleted, inspect GitHub before removing its matching local receipt or explicitly dispatching a replacement. A network error during dispatch can have an uncertain outcome; inspect the run list before retrying.

`setup-direct` verifies the personal Apple account, registers only the selected device if needed, and creates/imports a personal Distribution identity. The first use can require Lucas to approve a macOS Keychain prompt. No password belongs in chat or a repository.

`package` builds one signed Release archive, exports with a personal Ad Hoc profile containing exactly the shelf's iPhones (the configured iPhone plus any added with `share-shelf`), then verifies the exported IPA's signature, bundle/build identity, profile, and expiry. Signing configuration lives in `~/.config/uikit-app/direct.json`; private signing material never belongs in Git.

`direct` requires a private personal source repo and committed files, uploads an immutable app release, checks GitHub's size and SHA256, and updates the catalog only for the current main commit. Draft uploads are recoverable. It returns `available-in-shelf`, which means catalog availability, not physical installation.

Both delivery routes reserve build numbers in `~/.config/uikit-app/build-numbers`; direct retries retain their reservation in `direct-deliveries`. This prevents a TestFlight fallback from reusing a newer direct build's version. Preserve these files alongside local credentials when moving to another Mac.

The `catalog` release body contains schema 1 JSON. App releases contain signed IPA files and metadata. Catalog manifest assets contain temporary GitHub package URLs, never a PAT. The shelf resolves a temporary manifest URL with its read-only credential, validates it, then opens `itms-services`. Authorization is never forwarded to GitHub's asset host or the iOS installer.

Small release asset URLs currently have a five-minute JWT lifetime even when the blob-signature expiry is an hour. Use the earlier expiry. `setup-shelf-refresh` installs a user LaunchAgent that checks every minute and refreshes links with under two minutes left; it retains older manifests for two hours to protect in-progress installations. This requires the Mac to stay awake. Installed apps continue working without the Mac until their signing expires. Frequent manifest writes consume GitHub API limits; scaling to a large catalog will need a different install-manifest strategy.

The shelf client accepts an ignored `ShelfAccess.generated.json` bootstrap file (`{"token":"..."}`), imports it into the iPhone's device-only Keychain, and allows replacement in Settings. Its push workflow copies this file from `~/.config/uikit-app/shelf-access.json`; never substitute the broad gh OAuth token. This one-time credential setup is complete. If rotated, verify private artifact reads succeed and private AppShelf source reads fail, and check the GitHub token's permissions remain Contents and Metadata read-only for AppShelf-builds alone. Binaries intentionally contain a recoverable artifact-only bootstrap credential, like Hop.

`setup-shelf-installs` opts this Mac into automatic installs for the same iPhone as `direct.json`, saving its UDID in `~/.config/uikit-app/shelf-installs.json`. The existing minute refresh reads installed versions through CoreDevice and installs missing or newer catalog apps, without launching them. Same or newer device versions are preserved. It reuses local signed IPAs, caches downloaded packages, and checks checksums, app identity, signatures, and the shelf's current device-set profile before installing. Installation has a separate lock and does not hold the catalog lock. An unreachable or locked device, failed install, or failed verification is left for a later refresh. USB or an available paired wireless connection is required; this is not internet-based remote management. Removing `shelf-installs.json` disables automatic installs. Logs are in `~/Library/Logs/uikit-app/shelf-refresh{,-error}.log`.

Do not claim installation or update success from HTTP, simulator checks, or catalog availability. The Mac emits `installed-on-device` only after reading the exact version/build back from the phone; it never launches the app. Manual installation through AppShelf still uses iOS confirmation. TestFlight remains available through the existing CLI as fallback.

## Sharing the shelf

`uikit-app share-shelf --device <UDID> --name <device-name>` shares every shelf app with another person's iPhone at no extra cost. It registers the iPhone with the personal team (up to 100 iPhones per membership year; the Apple name is reduced to plain ASCII), records it in `~/.config/uikit-app/shelf-sharing.json`, and re-signs each catalog app, AppShelf first. Profiles contain exactly the configured iPhone plus every shared iPhone; catalog entries record that set in `deviceSet`.

A share run first re-signs every outdated catalog package in parallel (four at a time) and adds them to the catalog in one update, so in the usual case every app is ready before the request page shows the install link. Each quick re-sign it downloads and verifies the published IPA, requires a single app bundle without nested code, fetches the Ad Hoc profile for the new device set under the same capability revision as the embedded profile (whose name records it), requires the new profile's entitlements to equal the old one's, swaps `embedded.mobileprovision`, re-signs the bundle with its existing entitlements, verifies the signature, team, devices, and entitlements again, and publishes it as release `<Name>-<build>-<commit12>-<deviceSet>` with the same version, build, and publication date. That takes seconds per app and leaves installed builds current, so nobody sees an update. Apps whose quick re-sign failed are retried one at a time, AppShelf first; if the quick path fails again, the app is rebuilt from the catalog's exact `sourceCommit` locally instead, never main HEAD: a cached HTTPS checkout in `~/Library/Caches/uikit-app/Resign/<Name>` (with AppShelf's ignored artifact credential copied in) goes through the normal `direct` delivery, which waits up to 15 minutes on the app's delivery lock instead of racing a push, may replace the catalog entry of that same commit even when main moved, and marks the entry `silent` so no announcement goes out. It does not depend on GitHub Actions or runners. A damaged checkout is deleted and cloned again once; a cataloged commit that no longer exists on GitHub needs a new push. Failures are remembered per app, commit, and device set in `shelf-resign-failures.json` and retried after 30 minutes, doubling up to daily; the minute refresh restarts them on that schedule even without access requests. A new device set or commit, Try Again in AppShelf, or a manual `share-shelf` run retries immediately (background runs pass `--automatic` and keep the backoff). After AppShelf, the command publishes the invite and makes up to three passes over apps that are still not current, so builds that landed with an older set are caught. If AppShelf, the invite, or the request page fails, the other apps are still re-signed, so removals take effect everywhere else, and requests show the failure.

The invite is the current AppShelf IPA and its manifest in a secret gist under `lucaswkuipers`, printed as an `itms-services` link and a QR code (`~/Library/Caches/uikit-app/ShelfInvite/AppShelf-invite.png`). The link uses the gist's latest-revision manifest and stays the same across updates; the IPA is referenced by blob hash, and the command checks that GitHub's five-minute raw cache serves the update. Anyone with the link can download AppShelf and extract its artifact-only token, but iOS installs it only on registered iPhones. Shared users get installs, CloudKit notifications on their own iCloud account, and links that need this Mac awake. Mac-assisted installs stay limited to the configured iPhone and accept any package whose profile includes it. Every app currently requires iOS 27.

Rerun `share-shelf` without options to retry and reprint the invite. `share-shelf --remove <device-name-or-UDID>` revokes an iPhone: everything, including the invite's AppShelf, is re-signed without it, so it can no longer install or update anything. Apps already on that iPhone keep running until their profiles expire (Ad Hoc has no per-device kill switch), and its AppShelf can still read the catalog until the artifact token is rotated. The iPhone stays registered with Apple; never disable it automatically. Do not claim a shared install worked until that person confirms it.

## Access requests

`uikit-app setup-shelf-requests` deploys `CLI/ShelfRequests/worker.js` as the `appshelf` Cloudflare Worker on the owner's free account (the only account in `wrangler whoami`, pinned as `account_id`), with a free D1 database (`appshelf-requests`, schema in `CLI/ShelfRequests/schema.sql`). Wrangler 4.143.0 runs with the CLI's own npm cache and a minimal environment, so agent variables never switch it into non-interactive account changes; the first login is a browser sign-in using the command setup prints. Each deploy passes the admin token with `--secrets-file`, and the worker rejects admin calls when the token is missing or short. `~/.config/uikit-app/shelf-requests.json` keeps the worker URL and token; neither belongs in Git. Setup writes the worker URL to the catalog's `invitation` field, the base of the personal invite links AppShelf creates. The bare URL still works as a generic request link.

The page offers a Profile Service configuration profile signed with the personal Apple Distribution identity; rerun setup after renewing that certificate. After the visitor installs it in Settings, iOS posts the UDID, model, build string, and device name to `/enroll`, and the worker redirects Safari back to the page, which polls the request's status. Nothing stays installed. The worker strips control and direction-override characters, sends computers and malformed posts back with an explanation, keeps one open request per iPhone, and caps open requests at 20 per week atomically. The device signature is not verified, so a generic request waits for the owner's approval before the page shows the install link; approving an iPhone that is already in the set only refreshes its status.

The worker turns away iPhones below the catalog's minimum iOS (judged from the build string: iOS 26 and later report builds numbered three below the major version) before anything is recorded, so they never use one of the 100 device slots; an invite stays unused for after the update. Personal invites skip that approval. AppShelf's Invite Someone creates a `ShelfAccessRequest` record named `invite-<32 hex>` with status `invited` and the person's name, then shares `<invitation>?invite=<token>` as a link and QR code. The `refresh-shelf-requests` launch agent, which `setup-shelf-requests` installs to run every 15 seconds, signs a Profile Service profile whose enrollment URL is `/enroll?invite=<token>` and uploads it to the worker's `invites` table, deletes invites unused after seven days, and moves cancelled or expired unused invites to `cancelled_invites` once CloudKit confirms the record is gone, so their page says so instead of waiting for the Mac. The invite page greets the person by name and derives its state from the token, so reopening the link anywhere shows real progress. Enrollment through an invite claims it atomically for that iPhone (taking over an open request from the same iPhone); a used invite returns its own iPhone to the page and sends any other iPhone through the generic approval path. The relay approves an invited request directly under the invited name, deletes the invite record, and never notifies the owner, because the subscription only fires on `waiting` records. Used invites stay on the worker so the link keeps working.

A pending request from an iPhone that is in the device set and already has a `ready` or `shared` record is recorded as `shared` and goes straight to `ready` on the worker without another approval, since the install link only works on registered iPhones. The same 15-second agent relays other new requests into CloudKit `ShelfAccessRequest` records (Publisher role only), which notify the owner's AppShelf through the static-text `shelf-access-requests-v1` subscription on `status == "waiting"`. AppShelf writes `approved`, `declined`, or `remove`; the Mac reads records again by name before every change, so it never overwrites a newer decision. Statuses are `waiting`, `approved`, `retry` (Try Again, which also clears the backoff), `preparing`, `ready` (AppShelf installable), `shared` (with any apps still preparing listed in `detail`), `failed`, `remove`, `removing`, and `remove-failed`. While holding `shelf-share.lock`, the refresh registers approved iPhones and removes revoked ones (a removal also clears AppShelf's backoff); it then starts a detached `uikit-app share-shelf --automatic` in its own session at utility priority (log: `~/Library/Logs/uikit-app/shelf-share.log`). The minute refresh restarts one, at most every 10 minutes, while apps are outstanding or records are unfinished, except while a failed AppShelf build waits for its retry time, since nothing can progress before AppShelf does. Each run gives the worker the invite's blob-pinned manifest link before marking requests ready, finishes requests from the local device set, deletes completed removals, lists command-line additions as `shared` records so they can be removed in AppShelf, and keeps only the newest record when an approved iPhone asked again. Declined requests are deleted; the visitor may ask again. Each meaningful step is also written, best effort, as an owner-only `ShelfActivity` record (`message`, `person`, `level` info or error) for AppShelf's Activity screen; the 15-second agent prunes entries older than 30 days hourly, and a failed write never blocks the flow.

Before first use, deploy the record type: save a CloudKit management token with `xcrun cktool save-token --type management`, import `CloudKit/schema.ckdb` from the AppShelf repository into Development with `xcrun cktool import-schema --team-id AR7T5G5Z83 --container-id iCloud.com.lucaswkuipers.AppShelf --environment development --file CloudKit/schema.ckdb`, then deploy the schema to Production in CloudKit Console. The owner's iCloud account needs the `Publisher` role; AppShelf shows Sharing only when it can read these records, and reports a rejected subscription in the Sharing footer. Verify the whole path with a real request and notification before telling anyone it works. Run `./Tests/worker-check.sh` after worker changes; it serves the worker locally and needs no login.
