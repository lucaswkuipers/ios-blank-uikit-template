# Programmatic UIKit template

`CLI/ShelfInstalls.swift` optionally reconciles catalog apps with the actual installed versions on the one configured personal iPhone. `setup-shelf-installs` enables it in the existing minute refresh. Only install signed personal Ad Hoc packages after validating catalog checksum, app identity, profile, and target device. Never launch apps, downgrade a newer device version, or use last-opened Keychain receipts as installation evidence. Installation runs outside the catalog lock and failures retry without failing catalog refresh. A physical `installed-on-device` result requires reading the installed version back from CoreDevice. Remove `~/.config/uikit-app/shelf-installs.json` to disable it.

`XcodeTemplate/iOS/Application/Programmatic UIKit App.xctemplate` is the source of truth for app source files, assets, and Info.plist. `CLI/main.swift` copies it and fills `CLI/project.pbxproj`; keep that project's build settings consistent with TemplateInfo.plist when changing template defaults.

Install the Swift CLI with `./CLI/install.sh`. Personal signing defaults live outside the repository in `~/.config/uikit-app/config.json`; never add credentials here. `AgentSkill/uikit-app` is shared with Codex and Claude through their skill-directory symlinks.

Validate generator changes by creating a fresh scratch app and running `uikit-app check` on it. The optional check builds only for the simulator. Delivery verifies the signed Release archive; do not add a redundant Debug device build. Report simulator, signed archive, and TestFlight evidence separately from physical-device testing. Keep generated apps and build products outside the repository.

`CLI/TestFlight.swift` implements personal internal-only delivery; `CLI/AppRegistration.swift` bridges the asc CLI session to browser-free registration and tester enrollment. Keep the fixed personal team guard, remote account verification, single-tester group checks, and internal-only export setting. Run `./Tests/run.sh` for local behavior checks. End-to-end TestFlight validation additionally requires a real personal-account upload; never equate local tests with delivery.

Interactive sign-in must inherit the terminal's foreground process group. Foundation `Process` creates another group on macOS, causing password input to suspend the helper. Keep the `posix_spawn` launcher for this path. Validate changes with `./Tests/run.sh --interactive` in a PTY, entering the literal `dummy-local-input` at the test prompt; it never contacts Apple.

`CLI/GitHub.swift` creates only private repositories owned by `lucaswkuipers`; `CLI/CI.swift` installs a repository-scoped Mac runner and waits for push-triggered delivery. Keep the personal account/remote/visibility guards, personal commit identity, and scaffold `[skip ci]` marker. `publish` requires reviewed, committed work on main and must verify the personal availability result for the route saved in `.uikit-app.json`. This Mac defaults new apps to AppShelf following a verified phone install/update of the push-built CLIDeliveryCheck build 5. Legacy projects without delivery metadata retain TestFlight. Use `create --local-only` for disposable generator validation; test actual repository/CI changes against a private personal app repository, never a public template or amo repository.

`CLI/Direct.swift` packages personal Ad Hoc apps for exactly the shelf's iPhones: the configured iPhone plus those in `shelf-sharing.json`. `CLI/ShelfSharing.swift` registers (approves) and removes shared iPhones, re-signs outdated catalog packages in place (same build, new profile) and falls back to rebuilding their cataloged commits on this Mac, without announcements, and publishes the AppShelf invite to a secret gist: a stable latest-revision manifest URL that references the IPA by blob hash. Never put the invite in a public repository; anyone with the link can extract the artifact-only token. `CLI/ShelfRequests.swift` and `CLI/ShelfRequests/worker.js` implement self-service access requests: a free Cloudflare Worker captures UDIDs through a signed Profile Service profile, a 15-second `refresh-shelf-requests` launch agent syncs invites and relays requests to owner-only CloudKit `ShelfAccessRequest` records, and an approval starts a detached, locked `share-shelf` run that re-signs every app in parallel before the page offers the install. Rebuilds use the cataloged commit under the app's delivery lock, with per-app failure backoff; never dispatch workflows or rebuild main HEAD for a device change. Generic requests need approval because the device signature is not verified; personal invites (single-use `invite-<token>` records created by the owner's AppShelf, each with its own signed profile) are the owner's approval in advance. Read records by name before changing them, keep the subscription's notification text static, and keep the Worker's admin token and CloudKit keys out of Git. Run `./Tests/run.sh` and `./Tests/worker-check.sh` after changes; neither needs a login.

Generated apps include `ShelfVersionReceipt.swift` and a separate Keychain access group for version/build/date reporting on activation. Preserve each app’s default private group first; never put artifact credentials in the shared reporting group. Shelf status reflects the last opened build, not confirmation of installation or detection of uninstall.

`CLI/ShelfNotifications.swift` optionally publishes Apple CloudKit announcements after working shelf install links are committed. Its `shelf-notifications.json` and private key stay in the local configuration directory; do not bundle them. CloudKit container `iCloud.com.lucaswkuipers.AppShelf` belongs only to personal team `AR7T5G5Z83`. Stable announcement record IDs prevent duplicates when success responses or the sent-state cache are lost. The minute refresh retries pending latest builds; manifest refreshes do not create new announcements. Notifications have no added paid provider. AppShelf must have permission and an iCloud subscription; accepted publication does not prove display on Coppertino.

Direct delivery signs embedded application and extension targets with individual personal Ad Hoc profiles and verifies every exported bundle and build. The optional `.uikit-app.json` fields `xcodeProject` and `scheme` select an Xcode project generated inside the repository, such as a Unity iOS export under `build/`; its main product must match `name`. Unity cache folders are excluded from source fingerprints, while Assets, Packages, and ProjectSettings remain covered. An optional `prepareScript` runs a repository-local Swift script before packaging and must leave tracked sources unchanged; use it to regenerate exports during both publishing and device-sharing rebuilds. Quick re-signing still falls back to a full rebuild for nested code.

Catalog writes reserve headroom under GitHub's 125,000-character release-description limit by reducing the largest embedded PNG thumbnails until the encoded catalog fits 100,000 bytes. Original app icons, artifact-release metadata, installation identities, links, and version receipts are preserved. Thumbnail compression runs on every catalog write, so large catalogs cannot break the install-link refresh.
